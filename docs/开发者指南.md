# 开发者指南（架构与扩展）

本指南面向在本平台（collector 应用 + gocordis 框架）上开发组件与插件的工程师。所有代码位置、类型名、契约均对照当前代码校验。

---

## 1. 双仓与边界

| 仓库 | 角色 |
|---|---|
| `go-cordis`（模块 `dynamic-runtime`） | 框架：运行时内核、扩展（config/configwatch/console/procplugin/patch/bundle/loader/observe/…）、控制台（前端 + 服务端）、插件契约与构建工具 |
| `industrial-data-collector`（模块 `gocordis-csv-collector`） | 应用：采集领域层（source-unit、解析、存储、调度、台账）、组合预设、领域 hub 词汇、部署配置 |

**边界判据**（论文的声明式组合语义）：
- 组合机制（管线/补丁/发现/生命周期）→ 框架；组合内容与领域词汇 → 应用
- 控制台是“第二个 Cordis 应用”：永远不含领域词（检查点：框架内不得出现“采集/报警”等领域字符串）
- 领域判定（如“过期日无数据 = 终态”）属于应用 executor，不属于框架

## 3. 运行时核心概念（gocordis）

- **组件与 Fiber**：`config.ComponentConfig{ID,Type,Config,Enabled}` 经工厂创建组件；每个激活是一个 Fiber（Pending/Active/Failed/Gone），由 Controller 调和收敛
- **Capability**：`runtime.NewKey[T]` 声明能力；Provide 独占、Require 消费（`runtime/component.go`）
- **Effect**：`ctx.Effect(func() (cleanup, error))` —— 一切注册（页面、查询、进程）都是激活持有的可逆效果，卸载/调和自动撤销
- **观察流**：hub 观察事件 → SSE → 客户端只失效不携带状态

## 4. 组合管线（configwatch.ComposeDocument）

`extensions/configwatch/compose.go` 是唯一解析管线，层序（后层按 id 整行覆盖前层）：

```
bundles（extensions/bundle 注册表，来自 bundles = [...] 键）
  → 插件发现（extensions/console/procplugin.DiscoverPlugins，PluginDir 非空时）
    → 领域 Layer（应用注册，如 collector 的 SourcesLayer）
      → 显式 [[components]] 行
→ PostMerge 钩子（如向 query-provider 注入 source_definitions）
→ 行身份校验
```

- 每个 Layer 声明 `ConsumedKeys`（其消费的顶层键），未知顶层键仍然报错
- **补丁不在管线内**：`extensions/patch` 的有序补丁（remove/replace/insert）由宿主在调和前施加（`app/host/host.go` 的 `applyOverlay`：控制台补丁在前，`--patch` 运维层在后、最后生效）
- 框架自带 `tomlParser` 已委托同一管线（`extensions/configwatch/toml.go`）

## 5. 组件自描述（manifest.toml）

每个 `components/<包>/` 内嵌 `manifest.toml`（`go:embed` + init 注册进 `internal/pluginmeta`），声明该包提供的组件类型（kind/capability/显示名）。`app/config/validate.go` 的类型表由各包清单聚合生成——**不要手工维护中心表**。当前聚合 27 个类型，清单见各包 manifest。

## 6. 领域层：source-unit

- **profiles 合成**：`[[sources]]` + `profiles = [...]` 由 `app/sourcecomp` 的 `SourcesLayer` 解析合并，展开为 `source-unit:<id>` 组件行，并向 query-provider 注入 `source_definitions`
- **采集执行**：`app/collector/executor.go` —— `Recovery.Plan()` 合成窗口 → 逐 `collectOne`：`Source.List` → 分类错误 → 逐文件解析/入库 → `State.End`
- **状态判定**（`collectOne` 的 ErrNotFound 分支）：目录缺失 + **过期日且超出宽限**（`no_data_grace_hours`，默认 6 小时）→ `StatusSkipped`（终态“无数据”）；目录缺失 + **当天或宽限期内** → `StatusPending`。其他一切错误（网络不可达=ErrUnavailable、权限、超时、IO）→ `StatusFailed` 进失败账本重试。Skipped 行保留在补采窗口内静默复查（迟到投递可翻转），但被计划列表排除（`StatusOf` 过滤）——显示终态与机械复查解耦
- **Skipped 可复活**：不阻断日历缺口合成——目录后补时（窗口内）重新采集翻转为成功
- **元数据双通道**：`metadata_source = "inline"`（默认，`path_metadata` 规则内联）或 `"component"`（Require path-metadata 组件的 extractor capability；与内联规则互斥）
- **状态持久化**：`state_type = file-state`（`state/<源>/collection-state.json`）或 `memory-state`（默认，仅演示）

## 7. 控制台（extensions/console）

- **host**：每激活一个 Composition Registry + hub；UIComponent 提供 UIHostKey/HubKey 能力
- **三种贡献**（全部 Effect 持有、可逆）：`ui-page` / `ui-panel`（声明式视图栈）、`ui-client`（前端模块）、`plugin-explorer`（编程式）
- **hub 命名查询/命令**：应用桥（consolebridge）注册领域词汇；当前契约：查询 `sources/collections/collection/files/failures/observations/schedule/plan/effective-config/logs`，命令 `trigger`；proc 插件可经 procplugin 追加（如 demo 的 `alarms/ack-alarm`）
- **webui 端点**：`/api/ui/pages|panels|client-modules`、`/api/query/<名>`、`/api/command/<名>`、`/api/stream`（SSE）、`/api/plugins[/…]`、`/api/meta`、`/api/fleet`、`/client-modules/<名>/…`（插件目录同源静态挂载）
- **渲染器注册表**（`web/console/src/views/registry.tsx`）：块/页面/面板三种 keyed 注册；内建 palette（table/kv/list/stats/trend/query-table）与第三方同路径；未知类型优雅回退
- **投影 seam**（`web/console/src/lib/projections.ts`）：观察事件折叠为读模型 + 域计数器（collection/composition/source:<id>/all，250ms 合流）；视图按声明域失效
- **客户端模块加载**（`lib/client-modules.ts`）：启动时拉 manifest → 动态 import → register 门面（React/antd/api/注册表）；组合变更时增量加载新模块
- **logstore**（`extensions/console/logstore`）：应用日志环 + slog handler + 标准 "logs" 查询注册

## 8. 进程外插件（extensions/console/procplugin + loader/proc）

- 契约：行分隔 JSON-RPC 2.0 over stdin/stdout，握手 `GORIDIS-PROC-PLUGIN 1`，顺序调用，内建 shutdown
- 插件侧 SDK：`proc.Serve(map[string]proc.Handler{...})` —— manifest 声明的每个 query/command 名即同名方法
- 宿主侧：`ProcPluginComponent`（config：`dir`/`backend`/`queries`/`commands`）拉起进程、注册 hub 查询命令（Effect 持有），回收时杀进程并撤销
- 由 `plugins/<名>/manifest.toml` 发现生成组件行；生命周期与内置组件同权（可禁用/卸载）

## 9. 插件前端（web/plugin-kit + web/console）

- 插件前端是标准 npm 包：`src/ui.tsx`（JSX/TSX）+ 依赖（echarts 等），`gocordis-plugin-build`（esbuild 封装）自打包为单个 `ui.js`
- react/react-dom/jsx-runtime/antd 经构建别名指向 `@gocordis/plugin-kit` 的 shims，运行时取**控制台自己的实例**（单 React，hooks 安全）；其余库打入插件产物
- 入口约定：`plugins/<名>/ui.js`；服务端同源挂载 `/client-modules/<名>/`；入口 URL 目录形状使相对导入可用
- 信任模型：同源 + 操作员安装（与安装插件二进制同一决定）；渲染器持整页权限，不是沙箱

## 10. 组合预设（app/bundles）

`collector-core`（运行时骨架：scheduler/console-bridge/console-rows/query-provider/ui/plugin-explorer）与 `collector-console`（标准页面/面板）。`desktop.toml` 以 `bundles = [...]` 引用；显式行整行覆盖预设行。
