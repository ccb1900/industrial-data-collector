# 开发者指南（架构与扩展）

本指南面向在本平台（collector 应用 + gocordis 框架）上开发组件与插件的工程师。所有代码位置、类型名、契约均对照当前代码校验。

---

## 1. 双仓与边界

| 仓库 | 角色 |
|---|---|
| `go-cordis`（模块 `dynamic-runtime`） | 框架：运行时内核、扩展（config/configwatch/console/procplugin/patch/bundle/loader/observe/…）、控制台（前端 + 服务端）、插件契约与构建工具 |
| `industrial-data-collector`（模块 `gocordis-csv-collector`） | 应用：采集领域层（source-unit、解析、存储、调度、台账）、组合预设、领域 hub 词汇、部署配置 |

**边界判据**（论文的声明式组合语义）：
- 组合机制（管线/补丁/发现/生命周期）→ 框架；组合内容与领域词汇 → 应用
- 控制台是“第二个 Cordis 应用”：永远不含领域词（检查点：框架内不得出现“采集/报警”等领域字符串）
- 领域判定（如“过期日无数据 = 终态”）属于应用 executor，不属于框架

**依赖 gocordis 的更新方式**（模块名 `dynamic-runtime` ≠ 仓库路径 `github.com/ccb1900/gocordis`，`go get @main` 动不了 replace）：框架改动 push 之后，跑 `scripts/bump-cordis.sh [main|v0.1.0|<commit>]`——直连 GitHub 解析该引用的精确伪版本并改写 replace，跳过模块代理的分支缓存延迟。go.mod 必须钉死精确版本（可复现构建是模块系统的设计约束），"永远远程最新"即每次框架推送后执行一次该脚本。框架仓库打 tag 后可写干净版本号（`bump-cordis.sh v0.1.0`）。

## 3. 运行时核心概念（gocordis）

- **组件与 Fiber**：`config.ComponentConfig{ID,Type,Config,Enabled}` 经工厂创建组件；每个激活是一个 Fiber（Pending/Active/Failed/Gone），由 Controller 调和收敛
- **Capability**：`runtime.NewKey[T]` 声明能力；Provide 独占、Require 消费（`runtime/component.go`）
- **Effect**：`ctx.Effect(func() (cleanup, error))` —— 一切注册（页面、查询、进程）都是激活持有的可逆效果，卸载/调和自动撤销
- **观察流**：hub 观察事件 → SSE → 客户端只失效不携带状态

## 4. 组合管线（configwatch.ComposeDocument）

`extensions/configwatch/compose.go` 是唯一解析管线，层序（后层按 id 整行覆盖前层）：

```
bundles（extensions/bundle 注册表，来自 bundles = [...] 键）
  → 插件发现（extensions/console/procplugin.DiscoverPlugins，PluginDir 非空时）
    → 领域 Layer（应用注册，如 collector 的 SourcesLayer）
      → 显式 [[components]] 行
→ PostMerge 钩子（如向 query-provider 注入 source_definitions）
→ 行身份校验
```

- 每个 Layer 声明 `ConsumedKeys`（其消费的顶层键），未知顶层键仍然报错
- **补丁不在管线内**：`extensions/patch` 的有序补丁（remove/replace/insert）由宿主在调和前施加（`app/host/host.go` 的 `applyOverlay`：控制台补丁在前，`--patch` 运维层在后、最后生效）
- 框架自带 `tomlParser` 已委托同一管线（`extensions/configwatch/toml.go`）

## 5. 组件自描述（manifest.toml）

每个 `components/<包>/` 内嵌 `manifest.toml`（`go:embed` + init 注册进 `internal/pluginmeta`），声明该包提供的组件类型（kind/capability/显示名）。`app/config/validate.go` 的类型表由各包清单聚合生成——**不要手工维护中心表**。当前聚合 20 个类型（含 sqlserver-storage），清单见各包 manifest。

## 6. 领域层：source-unit + 四层声明模型

### 6.1 四层声明模型（app/sourcecomp/fleet.go）

配置的采集面是四层声明，装载时展开为 (机台 × 格式) 源实例：

```
defaults   横切默认（state_dir/date_policy/catchup/batch_size/稳定窗口）
sinks      连接即凭证（driver/dsn/file_table/lazy_connect）；驱动白名单
           memory/sqlite/mysql/postgresql/oracle/sqlserver——打错启动即失败
formats    一类数据文件 = 一张表的契约（match/table/sink/parser/columns）
format_groups  引用格式清单 = 机台类型的采集范围
machines   纯事实（no/ip/path/group/since/schedule/metadata）——不参与表构成
schedules  命名调度（name + cron/time）；机台经 schedule 字段引用——对象是机台
```

- 展开产物：`ResolvedSource`（id = `机台号-格式名`），path/since 来自机器，语义来自格式
- **引用完整性**：组引用缺失格式、机台引用缺失组或调度名、格式引用缺失 sink、
  日期无法归因（path 与 match 均无记号且非 specific/today/flat）——启动即响亮失败
- **match 词表**：YYYY/YY/MM/DD；含记号 → 文件名日期路由（filename_date_layout
  = match，pattern = 记号折叠为 *）；无记号 → 目录发现（pattern = match）
- **机台 path** 的日期段拆为 date_dir_layout，`{ip}/{no}` 模板替换
- 旧 profiles/resolver/machine_formats 已整体退役——不要重新引入

### 6.2 采集执行与实例制语义（app/collector/executor.go）

- **探针先行**：先 `Source.List` 后 `State.Begin`——无证据不物化
- **状态判定**（collectOne）：
  - 有文件 → Begin → 解析/入库 → Succeeded / Failed（坏行/坏文件）
  - **ErrNotFound（文件不存在）→ 不物化，Drop 旧遗留，日志 Skipped（不入台账、不重试、不告警）**——“没有”就是没有
  - ErrFileUnstable（稳定窗口内）→ 不物化，下次触发重探
  - 其他错误（网络不可达=ErrUnavailable、权限、超时、IO）→ Failed 可重试实例
- **两种逻辑不可混淆**：文件不存在（无实例、无需动作）≠ 网络不可达（Failed、持续重试）
- **装载迁移**（state.go NewFile）：旧语义 Skipped → 清除；Pending → 转 Failed（保留重试证据）
- **since 钳制**：Handle 与 PlanKeys 双处过滤 + 构造期一次性清扫早于 since 的旧记录
- **调度（以机台为对象）**：机台行 `schedule` 引用 `[[schedules]]` 的
  name；展开时引用调度的机台其 source group 写为合成内部组
  `__sched_<名>`，fleet 聚合出单个 scheduler 行（exclusive provider）按
  同名组发射——调度引擎与 source-unit 的 group 精确匹配链路零改动
  （空组 = 广播，供手动触发；未引用调度的机台不自动采集）

### 6.3 存储方言矩阵（app/storage）

五个 SQL 后端：sqlite / mysql / postgresql / oracle / sqlserver（go-mssqldb，纯 Go）。

| 环节 | 要点 |
|---|---|
| 类型映射 | `dialectTypes()`（sqlserver 用 NVARCHAR(4000)/DATETIME2） |
| 建表 | oracle/mssql 无 IF NOT EXISTS → `tableExists` 查系统目录按需建 |
| upsert | mysql=INSERT IGNORE；pg/sqlite=ON CONFLICT；**oracle/mssql=mergeUpsert()**（参数别名 cN，ON/INSERT 全经 quoteIdent） |
| 标识符 | `quoteIdent`：oracle 一律加引号（保留字安全，统一大写）；sqlserver 用 `[...]`；非常规名（自动列名）转义内嵌引号 |
| 日期绑定 | oracle 绑 `time.Time`（DATE 严格类型，字符串触发 ORA-01861），其余绑 ISO 字符串 |
| 分页 | oracle 11g=ROWNUM 包装；sqlserver=OFFSET/FETCH；其余=LIMIT/OFFSET |
| 列演进 | `existingColumns`（sqlite=PRAGMA / oracle=user_tab_columns / sqlserver=sys.columns / 其余=information_schema）+ ALTER ADD |
| 陷阱备忘 | oracle 保留字（SIZE/DATE…）裸写 ORA-00904；字符串绑 DATE 列 ORA-01861；COUNT 先于页面 SELECT（单连接自锁） |

**自动字段映射**：AutoColumns（columns 未声明 + header=true）→ 首批解码表头
建列（TEXT，列名=表头原文）；SQLite 单连接（SetMaxOpenConns(1)，QueryRows
COUNT 先于页面 SELECT）。漂移告警：首批评次后新增表头字段逐列 Warn。

### 6.4 台账（app/state）

- 实例制：状态文件只存异常与未完成；正常运营下为空是**预期**
- 装载即迁移：Skipped 清除 / Pending 转 Failed，随后回写压实
- Drop 连带清理 files/failedFiles 副档，不留孤儿失败账

## 7. 控制台（extensions/console）

- **host**：每激活一个 Composition Registry + hub；UIComponent 提供 UIHostKey/HubKey 能力
- **三种贡献**（全部 Effect 持有、可逆）：`ui-page` / `ui-panel`（声明式视图栈）、`ui-client`（前端模块）、`plugin-explorer`（编程式）
- **hub 命名查询/命令**：应用桥（consolebridge）注册领域词汇；当前契约：查询 `sources/collections/collection/files/failures/observations/schedule/plan/effective-config/logs`，命令 `trigger`；proc 插件可经 procplugin 追加（如 demo 的 `alarms/ack-alarm`）
- **webui 端点**：`/api/ui/pages|panels|client-modules`、`/api/query/<名>`、`/api/command/<名>`、`/api/stream`（SSE）、`/api/plugins[/…]`、`/api/meta`、`/api/fleet`、`/client-modules/<名>/…`（插件目录同源静态挂载）
- **渲染器注册表**（`web/console/src/views/registry.tsx`）：块/页面/面板三种 keyed 注册；内建 palette（table/kv/list/stats/trend/query-table）与第三方同路径；未知类型优雅回退
- **投影 seam**（`web/console/src/lib/projections.ts`）：观察事件折叠为读模型 + 域计数器（collection/composition/source:<id>/all，250ms 合流）；视图按声明域失效
- **客户端模块加载**（`lib/client-modules.ts`）：启动时拉 manifest → 动态 import → register 门面（React/antd/api/注册表）；组合变更时增量加载新模块
- **logstore**（`extensions/console/logstore`）：应用日志环 + slog handler + 标准 "logs" 查询注册

## 8. 进程外插件（extensions/console/procplugin + loader/proc）

- 契约：行分隔 JSON-RPC 2.0 over stdin/stdout，握手 `GORIDIS-PROC-PLUGIN 1`，顺序调用，内建 shutdown
- 插件侧 SDK：`proc.Serve(map[string]proc.Handler{...})` —— manifest 声明的每个 query/command 名即同名方法
- 宿主侧：`ProcPluginComponent`（config：`dir`/`backend`/`queries`/`commands`）拉起进程、注册 hub 查询命令（Effect 持有），回收时杀进程并撤销
- 由 `plugins/<名>/manifest.toml` 发现生成组件行；生命周期与内置组件同权（可禁用/卸载）

## 9. 插件前端（web/plugin-kit + web/console）

- 插件前端是标准 npm 包：`src/ui.tsx`（JSX/TSX）+ 依赖（echarts 等），`gocordis-plugin-build`（esbuild 封装）自打包为单个 `ui.js`
- react/react-dom/jsx-runtime/antd 经构建别名指向 `@gocordis/plugin-kit` 的 shims，运行时取**控制台自己的实例**（单 React，hooks 安全）；其余库打入插件产物
- 入口约定：`plugins/<名>/ui.js`；服务端同源挂载 `/client-modules/<名>/`；入口 URL 目录形状使相对导入可用
- 信任模型：同源 + 操作员安装（与安装插件二进制同一决定）；渲染器持整页权限，不是沙箱

## 10. 组合预设（app/bundles）

`collector-core`（运行时骨架：console-bridge/console-rows/query-provider/ui/plugin-explorer——**调度不在预设里**，由部署的 [[schedules]] 声明）与 `collector-console`（标准页面/面板：概览/采集/数据/插件）。`desktop.toml` 等以 `bundles = [...]` 引用；显式行整行覆盖预设行。
