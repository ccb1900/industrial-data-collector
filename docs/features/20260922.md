## 实现状态（2026-09-22）

**1. 文件备份 ✅**
- `[defaults] backup_dir`（+ 可选 `backup_keep_days`）经 fleet 下发到每个源单元。
- 采集成功的文件在标记完成**前**复制到 `<backup_dir>/<源id>/<业务日>/<文件名>`
  （临时文件 + rename；目标 size 匹配即跳过，幂等）。
- 严格语义：备份失败 = 该文件采集失败 → 进失败台账 → 下轮触发自动重试
  （写库 upsert 幂等，重跑安全）。
- `backup_keep_days > 0`：每轮采集后删除更早业务日的日期目录；目录名不是
  合法日期的一律保留。

**2. 扇入扇出并行采集 ✅**
- 源间（扇出）：`CollectionRequested` 处理器入队即返回，多源 worker 竞争
  进程级闸 `max_parallel_sources`（默认 4，first-call-wins）并行执行。
- 源内（扇出）：`files_per_source`（默认 1 = 串行）控制同日期多文件并发，
  结果按发现顺序扇入；取消的文件不进台账不进事件。
- 扇入：`internal/parallelism` 在途账本（Begin/Finish/Wait/DrainErrors）；
  `-once` 在 Trigger 后等账本清零并把全部作业失败汇回退出码——对外语义
  不变（任一采集失败 = 非零退出，计划任务照常告警）。

**3. 事件流可读性 ✅（Go 侧；控制台前端本期不动）**
- 根因：旧链路在整次 Handle 结束后**批量补发**，全部事件挤进同一秒，
  且"失败→重试→成功"的正常轨迹叠在一起无从分辨。
- 现在：事件在发生点经 `Executor.Observer` 即时发布，新增
  `CollectionStarted` / `FileStarted` 锚点（此前定义但从未发出），
  时间线形如 采集开始 → 文件开始 → 文件完成/失败 → 采集完成/失败，
  各占真实时点；多源并行互不串扰。query 组件把两个 Started 转为观察
  事件供 UI 时间线读取（前端渲染本期未改）。
