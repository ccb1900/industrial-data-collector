# 四层声明模型：机台清单 × 格式清单组 × 格式清单 × sink 清单（+ 命名调度）

日期：2026-09-19
状态：已定稿，本提交实现
前置：实例制台账（2e41f83）、自动字段映射（99c4a41）、减法提交（7a34634）

## 1. 背景与动机

部署规模：30 台机台、3 种机台类型，**同类型不保证同构**（目录布局、
格式集合、编码都可能不同），每台机台上有多类数据文件需要采集。

旧模型（profiles + machine_formats 枚举）在非同构世界里失败：
- 声明量 = Σ(类型格式数) 块 TOML，随异构性线性爆炸；
- 机器级差异（缺某格式、专属格式、投产日期不同）无法表达；
- 连接配置（dsn）混在数据语义里，换库要动几十处。

## 2. 模型：四层声明，职责正交

| 层 | 是什么 | 拥有的键 |
|---|---|---|
| **defaults** | 横切默认 | state_dir、date_policy、catchup_days、batch_size、file_stable_window_seconds |
| **sink 清单** `[[sinks]]` | 连接即凭证 | name、driver（sqlite/mysql/postgresql/oracle）、dsn、file_table、lazy_connect |
| **格式清单** `[[formats]]` | 一类数据文件的完整语义 = 一张表的契约 | name、match（文件名签名）、table、sink 引用、parser（encoding/header/allow_ragged/delimiter/skip_lines）、columns（可选，缺省表头自动映射）、metadata（路径/文件名元数据规则） |
| **格式清单组** `[[format_groups]]` | 机台类型的采集范围 | name、formats（引用格式清单名） |
| **机台清单** `[[machines]]` | 纯事实 | no、ip、path（含 {ip}/{no} 与日期词表 YYYY/YY/MM/DD）、group（引用格式清单组）、since、schedule（引用调度名）、metadata（机台静态元数据） |
| **命名调度** `[[schedules]]` | 自动采集的节奏 | name、cron（或 time 每日时刻） |

核心语义：
1. **表是格式的属性**。一张表 = 一个格式定义；同格式跨机台共享一张表，
   机台号（machine_no）作为数据列区分机台——机台不参与表构成。
2. **match 的日期词表决定路由模式**：match 含日期记号 → 文件名内嵌日期
   路由（文件名日期布局 = match）；match 无日期记号 → 目录内 pattern
   发现（日期目录来自机台 path 的日期段）。
3. **机台 path 的日期段**：path 中出现的日期词表段作为日期目录布局
   （root = 首个日期记号之前的静态前缀）。
4. **展开**：机台 × 其组的格式 → 源实例（id = `{no}-{format}`）。
   path/since 来自机器，match/parser/columns/table/sink 来自格式。
5. **实例制缺失语义**（承接 2e41f83，无巡检层）：采集时文件不存在 =
   无证据不物化（无实例、无重试、无告警）；网络不可达 = 可重试
   Failed 实例。缺失可见性由台账的空缺自然呈现。

### 调度层：以机台为对象

调度是**命名实体**（`[[schedules]]`，name + cron/time），机台行通过
`schedule = "<调度名>"` 引用——调度的对象是机台，不是格式组。"机台
属于哪个节奏"与"机台采哪些格式"（格式清单组）彻底正交：同一组机台
可以分属不同调度，同一调度下的机台可以采不同格式组。

实现：展开时引用了调度的机台，其 source 的 group 直接写为合成内部组
`__sched_<调度名>`；调度器行按同样的组名发射 `CollectionRequested`。
调度引擎与 source-unit 的 group 精确匹配链路零改动（空组 = 广播，
供手动触发；组不匹配的源跳过）。**未引用任何调度的机台不自动采集**
（仍可手动/watch 触发）。

### 覆盖链（单值键）
defaults → 格式 → 组 → 机台。机台层实际只拥有 path/since——交叉覆盖
场景被结构性消除。三条显式边界：
- **单 sink 边界**：一份数据一个去向；双库同步出界（交库间同步）。
- **模板键**：本期无（机台不参与表构成，{machine.no} 模板不需要）。
- **时间/条件覆盖**：出界——配置是声明不是运行时状态，临时变更走
  运维（改配置热加载 / --patch）。

### 机器级差异的处理
- 缺某格式：组里去掉 / 用按机器的独立组声明（罕见，显式优于隐式）；
- 机器专属列：新增格式定义（新表或同构扩展副本）——受控重复可接受；
- since 各异：机台行自持；
- 采集节奏各异：机台行各自引用调度（不引用则不自动采集）。

## 3. 引用完整性（启动即校验）

- 组引用的格式必须存在；机台引用的组必须存在；格式引用的 sink 必须存在；
  机台引用的调度名必须存在；
- match 必须含至少一个日期记号（v1 不支持无日期文件；flat/undated 走
  格式 `layout = "flat"` 或后续版本）；
- table/driver 合法性沿用现有校验（表名 ASCII 标识符、方言四选一、
  同表列集一致性）；
- 机台 no 全局唯一；格式名全局唯一；sink 名全局唯一；调度名全局唯一；
  调度必须给出 cron 或 time（二选一）。

## 4. 退役

- `profiles`（含全部 profile 级键）——被 四层模型 取代，直接删除；
- `[[sources]]` / `machine_formats` 旧展开声明——同上；
- legacy csv-collector 组件及其配置——已于 7a34634 删除；
- `no_data_grace_hours`——已于实例制废弃；
- `expect` / `inspection_lookback_days` 巡检层——随实例制废弃（缺失
  由台账空缺呈现），格式层残留的静默吞键一并移除。

## 6. 验收标准

1. 三份标杆配置在四层模型下 dump 展开与迁移前语义等价（源数、表、
   路由、since、调度组）；
2. 引用完整性：缺格式/缺组/缺 sink/缺调度/坏 since 任一 → 响亮启动失败；
3. laser 真实数据全量重跑（实例制，干净 state）：228 文件登记入
   LASER_FILES、15 张表 120,900 行（LASER_AAA 61,510）、0 伪任务；
4. 调度组路由 e2e（CSV-E2E-12）：组匹配的源采集、组不匹配跳过、
   无组广播（手动）全响应；
5. 全量测试绿、GOOS=windows 构建绿、文档验证脚本绿。
