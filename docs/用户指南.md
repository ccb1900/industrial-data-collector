# 用户指南（工业数据采集平台）

本指南面向**使用与运维**本系统的人员：如何启动、如何在控制台查看采集情况、如何配置数据源、如何安装插件。所有命令、路径、配置键均已对照当前代码校验（校验日期见文末）。

---

## 1. 这是什么

一套部署在工厂内网的**工业数据采集与监控平台**：

- 按业务日期从本地目录或 UNC 网络共享采集 CSV/文本文件，解析后写入 SQLite / MySQL / PostgreSQL / Oracle / SQL Server

**相对路径锚定**：配置里的全部相对路径（`state`、源根 `path`、`dsn`、`plugins`、补丁文件）一律相对**配置文件所在目录**解析——终端启动、双击 exe、Windows 计划任务（默认工作目录是 System32）行为完全一致，状态与数据绝不会散落到启动目录。
- 内置控制台（浏览器访问）查看采集任务、文件明细、失败账本、日志与数据
- 支持三类扩展：内置组件（编译进程序）、进程外插件（独立进程）、前端模块（控制台页面）

## 2. 快速开始

```bash
# 控制台 + 采集（常驻，含配置热加载与启动补采）
go run ./cmd/web-ui -config configs/desktop.toml -addr :8080
# 浏览器打开 http://localhost:8080

# 一次性采集（配合 Windows 任务计划 / cron）
go run ./cmd/csv-collector -config configs/laser.toml -once
```

两个入口共享同一套配置与数据目录。`web-ui` 启动时会自动执行**启动补采**（恢复补采窗口内的缺失批次），无需手动触发。

## 3. 控制台页面

菜单由配置声明，默认 4 页 + 插件贡献页：

| 页面 | 用途 |
|---|---|
| **概览** | 异常雷达：指标区（数据源/待处理/累计记录/失败文件）+ 「需要处理」异常置顶区（失败/等待 + 原因直显）+ 按日趋势 + 日志/事件流 |
| **采集** | **核心工作台（以源为中心）**：左侧选数据源 → 右侧采集状态日历（逐日着色，点日期联动）→ 当日采集详情 / 文件明细 / 该源失败账本 / 数据样本，单源“采集”按钮就在详情头部 |
| **数据** | 入库数据的浏览与查询：列由响应自适应（换业务换存储零改动），服务端分页，存储洞察列出每张暴露表的行数 |
| **插件** | 治理：所有组件与插件的启用/禁用、卸载/恢复、配置编辑（结构化编辑器）；插件贡献的页面（如报警示例）平级挂载在菜单 |

**联动规则**：采集页的文件明细、失败账本、数据样本都是**聚焦视图**——跟随“选中的源 + 日历上选中的日期”。未选择时显示引导提示，这是正常状态。

## 4. 采集状态语义（重要）

**实例制**：台账只记录真实发生过的采集。文件存在 → 产生实例；文件不存在 → **不产生任何记录**——“没有”就是没有，不是失败，也不需要重试。

| 状态 | 含义 | 后续 |
|---|---|---|
| **成功** | 文件已发现并采集入库 | 终态；补采不再触碰 |
| **失败** | 尝试了但出错：文件损坏、存储故障、**网络不可达（UNC 掉线）**——暂时故障 | 每次触发自动重试；文件晚到后采集成功即自动覆盖 |
| **等待写入**（瞬态） | 文件正处于稳定窗口内（仍在写入），本轮未采集 | 下次触发重探即得 |
| （无记录） | 该日期没有文件——**无证据不物化**，台账与采集历史中不存在 | 不存在“无数据”这种伪任务；没有数据不需要重试 |

**关键规则**：**网络不可达与文件不存在是两种逻辑**——前者是暂时故障（判定失败、持续重试、恢复后自动补齐），后者是事实（无记录、无需任何动作）。`since`（源生命周期下界，如机台投产日）之前的日期不计划、不物化。

**补采窗口**：`catchup_days`（默认各源配置，演示为 7 天）。窗口内没有成功记录的日期每次触发都会复查；窗口之外的日期不再追。窗口随日期每天滑动一天。

## 5. 日常操作

- **立即采集**：采集任务/概览页的按钮。可选日期（默认按调度策略，通常为昨天）。**点击即受理**：响应只代表任务已进入采集队列，成败与进度看事件流与任务列表（大窗口采集不会挂住页面）
- **确认报警**：报警示例页每行可确认（演示插件）
- **禁用/卸载组件**：插件页对每个组件执行；决策持久化在 `configs/desktop.toml.removed.json`，重启不丢
- **恢复组件**：插件页对已卸载组件执行“安装”

## 6. 配置

配置文件为 TOML，位于 `configs/`。整体装配顺序：

```
bundles（预设包：collector-core 运行时骨架 / collector-console 标准页面）
  → 插件发现（plugins/*/manifest.toml 自动生成组件行）
    → 四层清单（defaults / sinks / formats / format_groups / machines / schedules）
      → 显式 [[components]] 行（整行覆盖同名组件）
        → 补丁（控制台编辑持久化 + 运维 --patch 文件，最后生效）
```

### 6.1 四层声明模型（推荐且唯一受支持写法）

**机台清单是事实，格式清单是契约，组是分配，sink 是连接**——四层职责正交：

```toml
[defaults]                          # 横切默认（可被格式/组/机台覆盖）
state_dir = "../state"
date_policy = "yesterday"           # yesterday / today / specific(+specific_date)
catchup_days = 31                   # 停机后最多回看 31 天补齐
batch_size = 1000
file_stable_window_seconds = 0      # 文件稳定窗口（秒），防止读到写入中的文件

# ===== sink 清单：连接即凭证（换库只改这里）=====
[[sinks]]
name = "plant-oracle"
driver = "oracle"                   # sqlite / mysql / postgresql / oracle / sqlserver
dsn = "oracle://system:oracle@127.0.0.1:49161/XE"
file_table = "laser_files"          # 可选：文件登记表（每文件一行 + 表头存档）
lazy_connect = true                 # 连接失败不阻断启动，写入时重试

# ===== 格式清单：一类数据文件 = 一张表的契约 =====
[[formats]]
name = "aaa"                        # 全局唯一
match = "aaa_YYMMDD.log"            # 文件名签名（含日期词表 → 文件名日期路由）
table = "LASER_AAA"                 # 目标表；同格式跨机台共享一张表
sink = "plant-oracle"               # → sink 清单引用
[formats.parser]                    # 解析与编码属于格式
encoding = "gb18030"                # utf8 / gbk / gb18030 / big5 / utf16le / auto
header = true
allow_ragged = true                 # 容忍各行字段数不一致（设备导出常见）
# columns = [ ... ]                 # 可选；不写 = 表头自动映射（见下）

# ===== 格式清单组：机台类型的采集范围 =====
[[format_groups]]
name = "laser-set"
formats = ["aaa", "mainte1", "pwr"]   # 引用格式清单名

# ===== 机台清单：纯事实（加机台 = 加一行）=====
[[machines]]
no = "MT-001"                       # 机台号，随每行数据写进 machine_no 列
ip = "192.168.1.100"
path = '\\{ip}\\logs\\YYYYMM'          # {ip}/{no} 模板 + 日期词表段（→ 日期目录布局）
group = "laser-set"                 # → 引用格式清单组
since = "2025-03-01"                # 投产日期：之前的业务日不计划、不物化
```

**展开结果**：机台 × 其组的每个格式 = 一个源实例（id = `机台号-格式名`，如 `MT-001-aaa`）。路径与 since 来自机台，解析/列/表/sink 来自格式。

**自动字段映射（默认）**：SQL sink + `header = true` 时**无需声明 columns**——首个采集批次用解码后的表头自动建列（全部 TEXT，列名即表头原文，含中文）。GBK 等旧编码配好 `encoding` 后同样正确。显式声明 columns 可改列名/类型；`columns = []` 显式空数组会被拒绝。

**日期词表**：`match` 与机台 `path` 中的日期段只认四个记号——`YYYY`（2026）、`YY`（26）、`MM`（09）、`DD`（08），其余字符原样保留（`aaa_YYMMDD.log` → `aaa_260901.log`）。match 含日期记号 → 文件名日期路由；只有机台 path 含日期段 → 目录内 pattern 发现；两者都没有且非 specific 策略 → 启动报错（业务日无法归因）。

**调度（[[schedules]]）**：调度是命名实体，**对象是机台**——机台行通过 `schedule` 引用调度名，"机台属于哪个节奏"与"机台采哪些格式"（格式清单组）互不相干：

```toml
[[schedules]]
name = "nightly"
cron = "23 3 * * *"                 # cron 或 time = "05:00"（每日）二选一

[[machines]]
no = "laser"
path = "../res/laser/YYYYMM"
group = "laser-set"                 # 采哪些格式（格式清单组）
schedule = "nightly"                # 何时采（调度名）；不写 = 不自动采集
```

不同机台可引用不同调度（如 6 小时一次的频繁采集 + 每周日一次的补采）；未引用任何调度的机台不自动采集，仍可从控制台手动触发或由 watch 触发。

**引用完整性**：组引用不存在的格式、机台引用不存在的组或调度名、格式引用不存在的 sink、match 与 path 均无日期记号——任一都在启动时响亮失败，绝不静默丢采集。

**路径词表与跨平台**：路径中的 `\` 与 `/` 都视为分隔符，统一为主机原生风格（Windows 全 `\`，mac/Linux 全 `/`）。相对路径相对**配置文件所在目录**解析，与启动方式（终端/双击/计划任务）无关。UNC 共享仅 Windows 直达；mac/Linux 联调把共享挂载到本机后 `path` 写挂载点。

**机台号进表**：每行数据自带 `source_id` 与 `machine_no` 两个元数据列，跨机台共享一张表时用它们区分机台、做机台间聚合。机台行还可带 `[machines.metadata]` 补充静态业务元数据（产线、厂区等）。

**单源/直配场景**（无机台清单）：`[[sources]]` 直配一行（id/path/内联配置）仍然支持，适合单目录单格式的简单部署；有机台群时一律走四层清单。

### 6.2 补丁（控制台决策与运维覆盖）

- 控制台里的配置编辑/卸载决策，持久化为 `configs/desktop.toml.removed.json`（有序补丁），重启生效
- 运维可用 `--patch 文件` 提供只读补丁层，**在控制台补丁之后应用（最后生效）**，用于舰队级统一覆盖
- 补丁格式：`{"version":1,"patches":[{"op":"remove|replace|insert","id":"组件id","component":{...}}]}`

### 6.3 插件（完全自包含）

一个插件 = `plugins/<名称>/` 目录：

```
plugins/alarm-demo/
├── manifest.toml    # 声明：后端、前端、页面、查询/命令
├── main.go          # 进程外后端源码（go build -o alarm-demo . 构建）
├── alarm-demo       # 构建产物（可执行文件）
└── src/ui.tsx → ui.js  # 前端（npm run build 自打包）
```

安装他人插件：

```bash
scripts/install-plugin.sh @scope/my-plugin        # 从 npm registry
scripts/install-plugin.sh ./my-plugin-0.1.0.tgz   # 离线 tarball
```

## 9. 常见问题

- **某天在日历/任务列表里没有出现？** 正常：实例制下“没有文件”不产生任何记录——不是失败，不需要处理。若数据迟到（文件后补），在补采窗口内触发采集即可补上。
- **文件还在写入就被触发了会怎么办？** 配置了 `file_stable_window_seconds` 时，窗口内仍被写入的文件本轮不采（不物化），文件稳定后的下轮触发自动补采。不会丢数据，也不会重复。
- **失败的任务会自己恢复吗？** 会。失败（含 UNC 掉线）保留在补采计划里，每次触发自动重试；文件晚到后采集成功即覆盖失败。
- **UNC 部署的两个 Windows 特有事项**：①以**计划任务/服务**运行采集器时，Windows 用机器账户（而非登录用户）访问共享——终端里能读、服务里被拒是凭据差异，不是路径问题；请让任务以有共享权限的域用户运行。②`state` 必须放在**本机磁盘**：SQLite 与文件锁在网络盘上会锁冲突甚至损坏，共享只用于放被采集的源文件。
- **跨平台路径怎么写？** `\` 与 `/` 都按分隔符统一（Windows 全 `\`，mac/Linux 全 `/`）；相对路径相对配置文件所在目录解析，与启动方式无关。
- **换数据库/加数据库？** 只改 sink 清单：五种后端（sqlite/mysql/postgresql/oracle/sqlserver）一个 `[[sinks]]` 块即可，格式清单里把 `sink` 指向新 sink 名。Oracle 用 go-ora URL（`oracle://user:pass@host:port/service`），SQL Server 用 `sqlserver://user:pass@host:port?database=name`。
- **重启后页面打不开/空壳？** 确认旧进程已退出：`pgrep -lf web-ui`。端口上挂着旧版本进程时会出现组合加载失败。
- **想看程序实际会加载什么配置？** `go run ./cmd/web-ui --dump-config -config configs/desktop.toml`（本机运维命令，输出真实值）。
- **部署加固**：`state/` 加单实例锁（第二个进程拒绝启动）；`plugins/` 目录内的后端可执行文件与前端模块会以服务账号身份运行/加载——**目录写权限必须仅限服务账号**，任何能写该目录的账号都等同主机权限。
- **控制台里的 DSN 显示为 `__REDACTED__`？** 控制台接口对敏感键（dsn/password/secret/token 等）做了脱敏展示；编辑保存时哨兵值自动还原为真实值，不会覆盖配置。
