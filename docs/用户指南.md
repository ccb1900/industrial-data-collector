# 用户指南（工业数据采集平台）

本指南面向**使用与运维**本系统的人员：如何启动、如何在控制台查看采集情况、如何配置数据源、如何安装插件。所有命令、路径、配置键均已对照当前代码校验（校验日期见文末）。

---

## 1. 这是什么

一套部署在工厂内网的**工业数据采集与监控平台**：

- 按业务日期从本地目录或 UNC 网络共享采集 CSV/文本文件，解析后写入 SQLite / MySQL / PostgreSQL / Oracle

**相对路径锚定**：配置里的全部相对路径（`state`、源根 `path`、`dsn`、`plugins`、补丁文件）一律相对**配置文件所在目录**解析——终端启动、双击 exe、Windows 计划任务（默认工作目录是 System32）行为完全一致，状态与数据绝不会散落到启动目录。
- 内置控制台（浏览器访问）查看采集任务、文件明细、失败账本、日志与数据
- 支持三类扩展：内置组件（编译进程序）、进程外插件（独立进程）、前端模块（控制台页面）

## 2. 快速开始

```bash
# 控制台 + 采集（常驻，含配置热加载与启动补采）
go run ./cmd/web-ui -config configs/desktop.toml -addr :8080
# 浏览器打开 http://localhost:8080

# 一次性采集（配合 Windows 任务计划 / cron）
go run ./cmd/csv-collector -config configs/windows-task.toml -once
```

两个入口共享同一套配置与数据目录。`web-ui` 启动时会自动执行**启动补采**（恢复补采窗口内的缺失批次），无需手动触发。

## 3. 控制台页面

菜单由配置声明，默认 6 项：

| 页面 | 用途 |
|---|---|
| **概览** | 采集运行总览：数据源/任务/记录数统计、按日趋势、最近任务列表 |
| **采集任务** | 核心页面：调度信息、补采计划、任务表；**点选一行任务**，下方“文件明细”表与右侧“采集详情”面板即展示该次采集 |
| **数据源** | 数据源单元列表，可对单个源触发采集 |
| **数据查询** | 按数据源/日期分页查询入库数据；列由入库表结构自适应（换业务换存储零改动），存储洞察列出每张暴露表的行数 |
| **插件** | 查看所有组件与插件：启用/禁用、卸载/恢复、编辑配置（结构化 JSON 编辑器） |
| **报警示例** | 插件自定义页面示例：数据来自进程外插件，渲染来自插件前端模块 |

**联动规则**：文件明细与采集详情是**聚焦视图**——它们展示“当前选中的那一次采集”。未选中时显示引导提示，这是正常状态。

## 4. 采集状态语义（重要）

**实例制**：台账只记录真实发生过的采集。文件存在 → 产生实例；文件不存在 → **不产生任何记录**（“没有”不是一条记录，而是一种被巡检监护的状态）。

| 状态 | 含义 | 后续 |
|---|---|---|
| **成功** | 文件已发现并采集入库 | 终态；补采不再触碰 |
| **失败** | 两类：①尝试了但出错（文件损坏、存储故障、**网络不可达**）；②**巡检异常**——画像声明 `expect = "daily"` 时，回看窗口内（`inspection_lookback_days`，含目标日）预期缺失 | 每次触发自动重试；文件晚到后采集成功即自动覆盖失败 |
| **等待写入**（瞬态） | 文件正处于稳定窗口内（仍在写入），本轮未采集 | 下次触发重探即得；只在采集进行中的瞬间可见 |
| （无记录） | 该日期没有文件且不在巡检窗口内——**无证据不物化**，台账与采集历史中不存在 | 不存在“无数据”这种伪任务；补采计划仍列出窗口内待复查日期（机械复查清单，非台账） |

**关键规则（实例制）**：台账只记录真实发生过的采集——文件存在才会产生实例。过期日无数据**不产生任何记录**（无证据不物化），"该有而没有"由**巡检**负责：画像声明 `expect = "daily"` 后，回看窗口内（`inspection_lookback_days`，含目标日）的预期缺失会生成**可重试的失败实例**，文件晚到后下次采集成功即自动覆盖。`since`（源生命周期下界，如机台投产日）之前的日期不计划、不巡检、不物化。**网络不可达（UNC 掉线）是暂时故障** → 判定失败并持续重试，恢复后自动补齐。

**补采窗口**：`catchup_days`（默认各源配置，演示为 7 天）。窗口内没有成功记录的日期每次触发都会复查；窗口之外的日期不再追。窗口随日期每天滑动一天。

## 5. 日常操作

- **立即采集**：采集任务/概览页的按钮。可选日期（默认按调度策略，通常为昨天）。**点击即受理**：响应只代表任务已进入采集队列，成败与进度看事件流与任务列表（大窗口采集不会挂住页面）
- **确认报警**：报警示例页每行可确认（演示插件）
- **禁用/卸载组件**：插件页对每个组件执行；决策持久化在 `configs/desktop.toml.removed.json`，重启不丢
- **恢复组件**：插件页对已卸载组件执行“安装”

## 6. 配置

配置文件为 TOML，位于 `configs/`。组合按层装配（上层可按组件 id 覆盖下层）：

```
bundles（预设包，如 collector-core / collector-console）
  → 插件发现（plugins/*/manifest.toml 自动生成组件行）
    → 显式 [[components]] 行（整行覆盖同名上层组件）
      → 补丁（控制台编辑持久化 + 运维 --patch 文件，最后生效）
```

### 6.1 数据源（推荐写法）

```toml
[profiles.csv_machine]          # 共享画像：采集方式
parser = "csv"
header = true
pattern = "*.csv"               # 文件名匹配；detect_content=true 时忽略扩展名按内容识别
file_stable_window_seconds = 0  # 文件稳定窗口（秒），防止读到写入中的文件
date_policy = "yesterday"       # 采集目标日期：yesterday / today / specific(+specific_date)
catchup_days = 7                # 停机后最多回看 7 天补齐
batch_size = 1000
state_type = "file-state"       # 采集台账持久化（务必配置，否则重启即忘）
state_dir = "./state"

[profiles.typed_sqlite]         # 入库画像
storage = "oracle-storage"
driver = "oracle"
dsn = "oracle://system:oracle@127.0.0.1:49161/XE"
table = "readings"
file_table = "source_files"
expose_console = true           # 该表暴露给控制台“数据查询”页

**自动字段映射（默认）**：SQL 存储 + `header = true` 时**无需声明 columns**——
首个采集批次用解码后的表头自动建列（全部 TEXT，列名即表头原文，含中文）。
GBK 等旧编码配好 `encoding` 后同样正确。显式声明 columns 可改列名/类型
（number 等）；`columns = []` 显式空数组会被拒绝。
lazy_connect = true

[[sources]]
id = "production-source"
path = "./data/production"
profiles = ["csv_machine", "typed_sqlite"]

[[sources.path_metadata]]       # 从文件名提取业务元数据（写入 product 列）
name = "product"
from = "filename"
pattern = "{product}.csv"
required = true
```

同一目录多种格式：多个 source 指向同一 `path`，用不同 `pattern`（如 `*.csv` 与 `*.dat`，后者可配 `encoding = "gbk"`）分工。

**分组调度**：不同机台组需要不同采集时刻时，调度器按组定向触发——
```toml
[[components]]
id = "scheduler"
type = "scheduler"

[[components.config.schedules]]
cron = "23 3 * * *"
group = "A"                # 只触发 A 组机台

[[components.config.schedules]]
schedule = "daily"
time = "05:00"
group = "B"                # 只触发 B 组机台
```
不声明 `group` 的调度为全员广播（向后兼容）。手动触发的“立即采集”不分组，作用于全部源。

**机台号进表**：UNC 路径按机台区分（`\\<机台IP>\logs`）时，每台机器一个 source，两种方式把机台号写进表：

1. **`source_id` 列（零配置）**：每行数据自带 `source_id` 列——把 id 命名成机台号即可，如 `id = "MT-001"`。
2. **静态元数据列（业务语义更强）**：

```toml
[[sources]]
id = "MT-001"
path = '\\192.168.1.100\logs'
profiles = ["fmt_a", "oracle_sink"]

[sources.metadata]          # 静态业务元数据，随每行入库
machine_no = "MT-001"
line = "A"
```

配合 sink 画像声明元数据列：`[[profiles.oracle_sink.columns]] from = "metadata" name = "machine_no" column = "machine_no" type = "text"`。

**几十台机台？用机台清单展开**：写一张机台表 + 每格式一个展开声明，框架自动生成全部源（机台号自动进元数据）：

```toml
# 机台清单（唯一一份：ip ↔ 机台号）
[[machines]]
ip = "192.168.1.100"
no = "MT-001"

[[machines]]
ip = "192.168.1.101"
no = "MT-002"
# ……其余机台逐行追加

# 每种格式一个展开声明（共享画像 + 文件 pattern + 日期路由）
[[machine_formats]]
path_template = '\\{ip}\logs'
profiles = ["fmt_a", "oracle_sink"]
pattern = "a_*.log"
date_dir_layout = "YYYYMM"                # 月份子目录 …\202609\
filename_date_layout = "a_YYYYMMDD.log"   # 文件名内嵌日期
id_suffix = "a"

[[machine_formats]]
path_template = '\\{ip}\logs'
profiles = ["fmt_b", "oracle_sink"]
pattern = "b_*.log"
id_suffix = "b"

[[machine_formats]]
path_template = '\\{ip}\logs'
profiles = ["fmt_c", "oracle_sink"]
pattern = "c_*.log"
id_suffix = "c"
```

展开结果：每机台 × 每格式一个源（id = 机台号-后缀），机台号随静态元数据进表。`path_template` 里的 `{ip}` 会替换为清单中的 ip；`pattern`/`date_dir_layout`/`filename_date_layout` 作为覆盖键进入各源配置。

**日期词表**：`date_dir_layout`/`filename_date_layout` 只认四个记号——`YYYY`（2026）、`YY`（26）、`MM`（09）、`DD`（08），其余字符原样保留（如 `a_YYMMDD.log`）。两位年份的文件（`a_260908.log`）直接用 `YY`。小时级子目录（`…/20260908/14/…`）无需专门记号：发现按日期目录递归，小时层交给目录结构本身。

**跨平台路径书写**：路径中的 `\` 与 `/` 都视为分隔符，采集前统一为主机原生风格（Windows 全 `\`，mac/Linux 全 `/`），不会因 `\ /` 混搭而误判"文件不存在"。UNC 共享仅在 Windows 上直接可达；mac/Linux 联调时把共享挂载到本机（如 `/Volumes/logs`、`/mnt/logs`），`path_template` 写挂载点即可，分隔符风格随意。

**机台分组**：不同机台用不同画像/格式时，给机台打组标签、让展开声明按组认领——同一实例内两组互不叉乘：

```toml
[[machines]]
ip = "192.168.1.1"
no = "MT-001"
group = "A"                # 机台分组标签

[[machine_formats]]
path_template = '\\{ip}\logs'
profiles = ["fmt_a", "oracle_sink"]
group = "A"                # 只展开 A 组机台
id_suffix = "a"
```

未声明 `group` 的展开声明认领所有机台（通用组）；同组内仍按格式各自成源。

常用源配置键（完整解析见 `components/sourceunit/component.go`）：`source_id`、`path`、`pattern`、`detect_content`、`encoding`（utf8/gbk）、`header`、`delimiter`、`skip_lines`、`columns`（from/name/column/type/required）、`date_policy`、`specific_date`、`catchup_days`、`batch_size`、`collection_mode`（batch/append）、`file_stable_window_seconds`、`dedupe_content_hash`、`state_type`、`state_dir`、`storage`/`sink`、`driver`、`dsn`、`table`、`file_table`、`expose_console`、`lazy_connect`、`metadata_source`（inline/component）、`layout`（dated/flat）、`allow_ragged`（容忍锯齿行）、`date_dir_layout`/`filename_date_layout`（日期路由词表 YYYY/YY/MM/DD）、`since`（源生命周期下界 YYYY-MM-DD）、`expect`（"daily"，声明预期节奏）、`inspection_lookback_days`（巡检回看窗口，默认 1）、`no_data_grace_hours`（**已废弃**，被巡检取代，仅告警）。

### 6.2 补丁（控制台决策与运维覆盖）

- 控制台里的配置编辑/卸载决策，持久化为 `configs/desktop.toml.removed.json`（有序补丁），重启生效
- 运维可用 `--patch 文件` 提供只读补丁层，**在控制台补丁之后应用（最后生效）**，用于舰队级统一覆盖
- 补丁格式：`{"version":1,"patches":[{"op":"remove|replace|insert","id":"组件id","component":{...}}]}`

### 6.3 插件（完全自包含）

一个插件 = `plugins/<名称>/` 目录：

```
plugins/alarm-demo/
├── manifest.toml    # 声明：后端、前端、页面、查询/命令
├── main.go          # 进程外后端源码（go build -o alarm-demo . 构建）
├── alarm-demo       # 构建产物（可执行文件）
└── src/ui.tsx → ui.js  # 前端（npm run build 自打包）
```

安装他人插件：

```bash
scripts/install-plugin.sh @scope/my-plugin        # 从 npm registry
scripts/install-plugin.sh ./my-plugin-0.1.0.tgz   # 离线 tarball
```

## 9. 常见问题

- **文件页是空的？** 它是联动视图——先到“采集任务”页点选一行任务。
- **任务列表里很多“无数据”？** 正常：补采窗口内目录不存在的日期已按“时间不可逆”规则关闭。若某天数据迟到（目录后补），在窗口期内触发采集仍会成功并翻转为“成功”。
- **文件还在写入就被触发了会怎么办？** 配置了 `file_stable_window_seconds` 时，窗口内仍被写入的文件不会被采集——该日期保持“等待数据”，文件稳定后的下轮触发自动补采。不会丢数据，也不会重复。
- **UNC 部署的两个 Windows 特有事项**：①以**计划任务/服务**运行采集器时，Windows 用机器账户（而非登录用户）访问共享——终端里能读、服务里被拒是凭据差异，不是路径问题；请让任务以有共享权限的域用户运行。②`state` 必须放在**本机磁盘**：SQLite 与文件锁在网络盘上会锁冲突甚至损坏，共享只用于放被采集的源文件。

**UNC 断网了会怎样？** 相关日期判为“失败”并持续重试，网络恢复后自动补齐；**不会**被误判为“无数据”。
- **重启后页面打不开/空壳？** 确认旧进程已退出：`pgrep -lf web-ui`。端口上挂着旧版本进程时会出现组合加载失败。
- **想看程序实际会加载什么配置？** `go run ./cmd/web-ui --dump-config -config configs/desktop.toml`（本机运维命令，输出真实值）。
- **部署加固**：`state/` 加单实例锁（第二个进程拒绝启动）；`plugins/` 目录内的后端可执行文件与前端模块会以服务账号身份运行/加载——**目录写权限必须仅限服务账号**，任何能写该目录的账号都等同主机权限。
- **控制台里的 DSN 显示为 `__REDACTED__`？** 控制台接口对敏感键（dsn/password/secret/token 等）做了脱敏展示；编辑保存时哨兵值自动还原为真实值，不会覆盖配置。
